# Attimo Conventions

These conventions fix the names that later phases build on: folders, naming, collision layers, groups, Input Map actions, the event bus and the player scene. Renaming any of them later means editing every scene and script that uses it.

## Purpose and sources of truth

- `attimo/project.godot` is authoritative for Input Map actions and collision layer names.
- `attimo/scripts/core/physics_layers.gd` (`PhysicsLayers`) is authoritative for layer bitmasks in code.
- This document mirrors both and adds the rules that have no engine representation (groups, folders, naming, bus rule, player-scene rules).
- `attimo/tests/smoke/test_conventions.gd` and `test_input_map.gd` run on every `bash attimo/tests/run.sh` and fail if this document, `project.godot` and `PhysicsLayers` drift apart.
- When you add a layer, group or action, change `project.godot`, the constants, this document and the tests in the same commit.

## Folder layout

The Godot project root is `attimo/` (D-01). `KayKit/` and the other raw asset packs sit in the repository root, outside the project, so Godot never imports them.

| Folder (under `attimo/`) | Contents |
|---|---|
| `autoload/` | Autoload singletons. Phase 1: `event_bus.gd` (EventBus). |
| `scenes/player/` | The Player scene and the Mannequin wrapper scene. |
| `scenes/camera/` | The camera rig scene (`camera_rig.tscn`, CameraRig). |
| `scenes/proto/` | Wrapper scenes for the Prototype Bits pieces (with collision). Phase 2 adds `moving_platform.tscn` and the Slope and Beam wrappers. |
| `scenes/test/` | Test scenes. `test_scene.tscn` is the Phase 1 main scene; `movement_gym.tscn` becomes the Phase 2 main scene. |
| `scenes/debug/` | Debug overlays such as the event log, the metrics overlay and the tuning panel. |
| `scenes/ui/` | Player-facing UI scenes (Phase 3: `crosshair.tscn`). |
| `scripts/core/` | Generic building blocks: `State`, `StateMachine`, `PhysicsLayers`. |
| `scripts/player/` | PlayerController, the animator, and `states/` (one script per movement state). |
| `scripts/camera/` | `CameraRig` and `CameraSettings` (camera tuning persisted in `user://settings.cfg`). |
| `scripts/ui/` | Player-facing UI scripts (Phase 3: `Crosshair`). |
| `scripts/gym/` | Gym-only helpers (`MovingPlatform`, `FallReset`). Phase 4 builds the real mechanisms. |
| `scripts/debug/` | Debug-only scripts. Strip or ignore in a release build. |
| `resources/` | Shared `Resource` instances. `resources/player/movement_default.tres` is the one `MovementConfig` that holds every movement number. |

| `assets/animations/` | Copied animation GLBs and the generated animation library. |
| `assets/animations/external/<family>/` | Conformed, mesh-free `.scn` sources of external clips (family `mixamo`; the UAL family is ready). Generated by `tools/conform_external_clip.gd`, never edited by hand. |
| `assets/prototype_bits/` | Copied Prototype Bits meshes and the shared texture. |
| `tests/` | `run.sh`, `run_smoke.gd`, `fixtures.gd` and `smoke/test_*.gd`. |
| `tools/` | Editor-time scripts run headless with `bash attimo/tests/run.sh --tool res://tools/<script>.gd`. |

Rules:

- Commit the `.import` and `.gd.uid` sidecar files. `.godot/` is ignored.
- Used assets are copied from `KayKit/` into `attimo/assets/`, never moved (D-04). `KayKit/` stays complete as a reference library.
- Never edit an imported GLB in place. Wrap it in your own scene.
- Raw external animation sources stay outside the project, in the reference library: `KayKit/Mixamo/` for Mixamo downloads, the Quaternius pack under `KayKit/Universal Animation Library[Standard]/`. FBX files never go inside `attimo/` (`test_asset_hygiene`). Raw Mixamo files are not committed (`KayKit/Mixamo/*.fbx` is in `.gitignore`).
- Retarget path (quick 261118-qbt, DEV-04): `tools/conform_external_clip.gd` writes the mesh-free `.scn`, `tools/clip_retargeter.gd` bakes the clip onto `Rig_Medium` through a `BoneMap` on `SkeletonProfileHumanoid` (families `mixamo`, `ual`, `rig_medium`), `tools/build_animation_library.gd` puts it into the library. The steps for a new clip are in `docs/ANIMATION-MAP.md`, External clips.

## Naming

- Files and folders: `snake_case` (`player_controller.gd`, `prototype_bits/`).
- Nodes and `class_name`: `PascalCase` (`VisualRoot`, `PlayerController`, `PhysicsLayers`).
- State nodes are named after the state, `PascalCase` (`Idle`, `Jump`). The node name is the state key.
- Signals: past-tense facts in `snake_case` (`jumped`, `landed`, `dash_started`, `movement_state_changed`).
- Input actions: `snake_case`. The `debug_` prefix marks debug-only actions that are not part of the player-facing list.
- Groups: `snake_case`.
- Constants: `UPPER_SNAKE_CASE`.

## Typed GDScript

- All gameplay code is typed. `debug/gdscript/warnings/untyped_declaration=2` turns every untyped declaration into a parse error. It applies to every script the engine parses, including `tools/` and `tests/`.
- Type loop variables (`for i: int in 30`), lambda parameters and locals (`var x: float` or `:=`).
- Use `##` doc comments on public members and a short class description on the first lines of every script.

## Collision layers

`.tscn` files store the **bitmask** (layer N = `1 << (N - 1)`), not the layer index. Code uses the `PhysicsLayers` constants and never magic numbers.

| Layer | Name | Bitmask | `PhysicsLayers` | Sits on it | Masked by |
|---:|---|---:|---|---|---|
| 1 | World | 1 | `WORLD` | Static geometry, moving platforms (AnimatableBody3D) | Player body, camera SpringArm (Phase 2), beam and aim rays |
| 2 | Player | 2 | `PLAYER` | Player CharacterBody3D | Enemy and hazard Areas that detect the player |
| 3 | Interactable | 4 | `INTERACTABLE` | Mechanism and interactable bodies and Areas | Targeting queries (Phase 4) |
| 4 | Enemy | 8 | `ENEMY` | Enemy bodies | Beam and rays, player hurt checks |
| 5 | Projectile/Beam | 16 | `PROJECTILE` | Beam and projectile hit shapes | Enemies, interactables, world |
| 6 | Hazard | 32 | `HAZARD` | Kill zones, damage volumes | Player-detecting Areas |
| 7-32 | (unnamed) | | | reserved | |

Rules:

- The thing being detected sits on its own layer. A detector (`Area3D`, ray, shape cast) finds it by setting its **mask**.
- Platforms, including moving ones, go on World (1). Kill zones go on Hazard (6).
- Layer 7 "Trigger" is recommended for checkpoints and is claimed in Phase 6. Until then it is documented here only and not named in `project.godot`.
- Layers 7-32 are reserved. A phase claims one by adding a row to the table above, a name in `project.godot`, and a constant in `PhysicsLayers`.
- Phase 1 Player: `collision_layer = 2` (Player), `collision_mask = 1` (World).

## Input Map

All input goes through Input Map actions. Game code under `autoload/`, `scripts/` and `scenes/` never polls raw keys, mouse buttons or joypads (`Input.is_key_pressed`, `is_physical_key_pressed`, `is_mouse_button_pressed`, `get_joy*`). `test_input_map` scans for these calls.

No project action has a gamepad event before Phase 13.

Keys are stored as physical keys (layout independent) with device -1 (all devices). Keyboard and mouse are bound now. The gamepad column is a reserved slot: nothing is bound, Phase 13 binds these to the same action names.

## Event bus

The `EventBus` autoload carries gameplay **facts** (D-10, D-11). Gameplay code only emits typed fact signals. It never calls audio, particles, tweens, time scale or camera effects. Feedback systems connect to the bus and react.

Exception: placeholder hit puffs in `scripts/debug` + `scenes/debug/hit_puff.tscn`, driven only by EventBus facts; real juice stays Phase 3+. `test_feedback_guard` allowlists exactly that one scene and still fails on any other particle node or on a gameplay script that names the puff.

| Signal | Payload | Emitted by |
|---|---|---|
| `jumped` | `position: Vector3` | `Jump.enter`, for ground jumps (Jump 1, Jump 2 and Jump 3, the pirouette jump). There is no air jump. |
| `long_jumped` | `position: Vector3, stage: int` | `LongJump.enter`; stage 1 first dash hop, then 2 and 3 on clean repeats on landing; the combo ends after 3 and the next hop restarts at 1 |
| `chain_stage_changed` | `stage: int` | `PlayerController` when the ground-jump chain stage changes (1, 2, 3 for Jump 1, 2, 3; 0 on reset) |
| `landed` | `position: Vector3, impact_speed: float` | `PlayerController._land` on floor contact; `impact_speed` is the downward speed at touchdown |
| `dash_started` | `position: Vector3, direction: Vector3, in_air: bool` | `Dash.enter` |
| `dash_blocked` | `position: Vector3, reason: StringName` | `PlayerController` when a dash press is refused by a lockout (quick 261120-dik); `reason` is `aim`, `pirouette`, `landing` or `takeoff`. Once per press, no cooldown or air dash spent, no buffering. A refusal by the cooldown or the spent air dash emits nothing. |
| `movement_state_changed` | `from_state: StringName, to_state: StringName` | `StateMachine` on every transition |
| `aim_changed` | `active: bool` | `PlayerController._tick_aim` when the aim hold starts (true) and ends (false), once per change; consumers `CameraRig`, `Crosshair`, `MannequinAnimator` |

Listeners: the debug event log now, juice (Phases 11-12), audio (Phase 14). A new fact is a new typed signal added in the phase that needs it. The bus holds no state and no logic.

## Player scene

- Structure: `Player` (CharacterBody3D) > `VisualRoot` (Node3D, pivot at the feet) > Mannequin wrapper scene (D-06). `VisualRoot`'s yaw is the facing: `PlayerController` owns it (camera-locked while aiming), and `face()`, `Dash`, `LongJump` and `CameraRig.recenter()` read it. The final hero (Phase 9) replaces the Mannequin under this node.
- Pose rule (Phase 3, DEV-01, the developer's approved deviation from the letter of D-01 and D-07, 2026-11-14): procedural lean and the Jump 3 pirouette are written by `ProceduralPose` on the Mannequin child of `VisualRoot`, inside the physics tick, pivoting at hip height. Never write lean, pitch or spin on `VisualRoot` itself. No pirouette starts when aim is held at takeoff, and an aim press or an air dash mid-spin finishes it within `pirouette_finish_time` (DEV-03, approved by the developer on 2026-11-15). Phase 11 squash and stretch is composed into the same Mannequin transform.
- Animation: the verb to state to clip map is `docs/ANIMATION-MAP.md` (MOVE-11, guarded by `test_animation_map`). A new verb lands with a kit clip or a composition row there, in the same change as its state.
- The state machine is the source of truth for movement (D-08). The animator listens to the local `StateMachine.state_changed` signal and never decides state.
- `Dash.slide` (quick 261118-qbt, DEV-04): a presentation hint set on enter, true for a ground dash started without aim. `MannequinAnimator` plays the retargeted `Running_Slide` (node `Slide`) for it and `ProceduralPose` adds no lean for it. Movement never reads it; there is still no slide state.
- Movement rules (Phase 2): the controller owns `move_velocity` (horizontal) and `vertical_speed`, applies gravity in half steps, and calls `move_and_slide()` exactly once per tick in `_physics_process`. It never stores the returned velocity as state. States only write `move_velocity`, `vertical_speed` and `gravity_scale`.
- All movement numbers live in `MovementConfig` (`resources/player/movement_default.tres`). Scripts never hold tuning literals.
- `platform_on_leave` is `DO_NOTHING`; the controller carries the horizontal platform velocity manually. `floor_max_angle` is 50 degrees and the floor snap length scales with speed.
- Aim (Phase 3, D-09, D-10): while `PlayerController.aiming` is true the controller owns the facing. `VisualRoot`'s yaw follows the camera's flat forward on every physics tick with no smoothing, `face()` and `face_now()` do nothing (Dash and LongJump keep the crosshair facing), and movement steers by the rig's true `yaw` instead of `steering_yaw()`, so W runs along the crosshair and A and D strafe. Aim never blocks a jump, but it blocks the dash (quick 261120-dik, amends D-12): `can_dash()` is false while aiming and a press is refused with the aim reason, so `DashLeft`, `DashRight` and `DashBack` are dormant (kept, unreachable, `MannequinAnimator.dash_node_for` still maps them). Ground speed in aim is `run_speed * aim_speed_factor`, reduced further by `aim_back_speed_factor` the more the input points behind the facing (`PlayerController.ground_target_speed`, used by Idle and Run); air speed is unchanged.
- Dash lockouts (quick 261120-dik): `PlayerController.dash_locked_reason()` is the one place that says why a dash cannot start, and `can_dash()` and `dash_press_starts_dash()` (the press check of `GroundState` and `AirState`) both use it. Locked: while aiming, during the Jump 3 / long jump stage 3 pirouette until it ends (`ProceduralPose.spinning`), in the landing window after touchdown (`dash_block_landing`, 0.1 s, timer `dash_landing_lock_timer`) and in the take-off window after a jump leaves the floor (`dash_block_takeoff`, 0.1 s, timer `dash_takeoff_lock_timer`; walking off a ledge is no take-off). Both timers tick in the physics step. A locked press is consumed: no buffering, no `Dash`, no cooldown, no air dash charge, `EventBus.dash_blocked` once and the twitch. The cooldown and the spent air dash are not lockouts and give no feedback.
- Blocked-dash twitch (quick 261120-dik): `PlayerController.dash_twitch_timer` starts on a refused press; `ProceduralPose.twitch_angle` is a half sine kick of `dash_blocked_twitch_deg` (6 degrees) over `dash_blocked_twitch_time` (0.1 s) added to the Mannequin lean (`total_lean()`), forward about the hips, no velocity and no clip.
- Dash crossfades (quick 261120-dik): `dash_in_blend` (0.06 s, ground locomotion into a dash clip), `dash_in_blend_air` (0.08 s, from a jump, long jump or fall) and `dash_out_blend` (0.15 s, out of a dash clip) are `MovementConfig` rows. `MannequinAnimator.apply_blend` writes them to the edge of the generated tree just before each travel, so they are live-tunable; the `Slide` edges and all other edges keep the tree's own 0.1 s.
- Teleports go through `teleport()`, which calls `reset_physics_interpolation()`.
- Stairs policy: risers up to 0.15 m are climbed without a jump, 0.18 m is the theoretical limit, taller ledges need a jump.
- The Mannequin wrapper scene wraps the imported GLB. The GLB is never edited in place (D-07).
- Capsule shape: radius 0.5, height 2.0, kept unchanged for Phase 2 (A2). The gym sign-off re-checks it against the Mannequin.
- `Mannequin_Medium` is about 2.2 m tall and faces +Z.
- Attach held items and effects to the bones `hand.r` / `hand.l`. The `handslot` bones exist only in the clip GLBs, not in the character GLB.
- The Dodge clips shift the root bone (Forward +0.25 m, Left/Right 0.5 m, Backward -0.65 m) and snap back. The library tool `tools/build_animation_library.gd` pins the root position of the four Dodge clips to their first key (`ROOT_PINNED`), so a dash does not slide the visual. The root rotation is untouched, because the strafe clips carry their direction in the root yaw. AnimationTree root motion is not used, because it also strips the root rotation.

## Camera

- Structure: `CameraRig` (Node3D, yaw) > `Pitch` (Node3D) > `SpringArm3D` > `Camera3D` (D-18). The rig is a sibling of the Player, never a child.
- The rig is `top_level` with physics interpolation OFF. It follows the interpolated player position in `_process`. Mouse look never scales by delta.
- The `SpringArm3D` masks World only.
- Framing is centered behind the character. The shoulder offset arrives only in aim mode (D-14, Phase 3).
- Framing numbers (quick 261118-qbt, DEV-05): `pivot_height` 1.4 m (slightly above the Mannequin's shoulder joint at 1.107 m; the Mannequin has a large head that reaches 2.2 m), arm (`SpringArm3D` spring_length) 3.6 m, default `pitch` -0.22 rad, pitch range -1.2 .. 0.75 rad, base FOV 78 degrees, `follow_rate` 22 and `vertical_follow_rate` 12 (1/s). The standing character reads in the lower part of the screen (shoulder at vertical ndc about -0.10, head top about 0.28, feet about -0.42).
- Lock (DEV-05, supersedes the Phase 2 D-15 airborne hold band "no fixed hard lock"): the vertical goal is the anchor height in every state. After the damping the rig is clamped to `max_follow_lag` (0.6 m, horizontal) and `max_vertical_lag` (0.35 m, vertical) from the anchor, so running, dashing (22 m/s), jumping and long jumping keep head and feet inside the view. At run speed the lag stays below the clamp (about 0.39 m at 8.5 m/s), so the damping still smooths the motion. `air_rise_band` is gone.
- Other systems change FOV and offset only through the additive per-source API on the rig (`set_fov_offset`, `set_offset` and their `clear_*` counterparts), so aim mode (Phase 3) and camera kick (Phase 11) never fight over the camera.
- `camera_recenter` (middle mouse button) turns the camera behind the character.
- Aim camera (Phase 3, D-13 to D-15): on `EventBus.aim_changed` the rig eases `aim_weight` within `aim_blend_time` and writes it through the `&"aim"` FOV source (`-aim_fov_delta`) and the `&"aim"` offset source (`aim_shoulder_offset` along Pitch-local X, one fixed right shoulder). The rig clears both once the weight is back at 0 and never touches them while aim was never held. While aiming, look sensitivity is scaled by `aim_sensitivity_factor`, `camera_recenter` and auto-follow are ignored, and the steering offset is zeroed on aim enter, so `steering_yaw()` equals `yaw`. Q is intentionally unbound: there is no shoulder swap action. The four aim camera numbers are `CameraRig` exports shown in the F2 panel and are never persisted.

- Aim target (quick 261118-qbt): the aim target is the world point under the screen-centre crosshair. `CameraRig.aim_target_point()` casts the camera centre ray (camera position along the camera -Z, no viewport query needed for a perspective camera without offsets) against `crosshair_ray_mask` (World now; Phase 4 may add Interactable and Enemy bits) and returns the first hit, else the point `crosshair_ray_length` (100 m) out. The ray starts level with the character (`CameraRig.aim_ray_start`), so geometry between the lens and the character is never the target. `last_aim_hit`, `last_aim_collider` and `last_aim_point` hold the last result, `aim_direction_from(origin)` returns the unit direction from a point to the target. Consumers find the rig through `PlayerController.camera_rig()`: `MannequinAnimator` feeds `aim_target_point()` to the `AimPoseModifier`, which aims from the shoulder (parallax-corrected), and the Phase 4 beam fires from the hand along `aim_direction_from(hand origin)`. It is a query, not an `EventBus` fact (the bus holds no per-frame state). `converge_distance` on the modifier is only the fallback without a rig. The ray length and mask are plain exports, not `aim_*` range floats, so the F2 panel keeps its four aim rows.

## Settings and debug

- Camera settings persist in `user://settings.cfg` through `ConfigFile` only. Values are clamped on load. No `Resource` is ever loaded from `user://`.
- Debug overlays live under `scripts/debug/` and `scenes/debug/`. They start hidden, are toggled by `debug_` actions and are stripped in Phase 15 (REL-03).

## Engine and tooling

- Pinned engine: Godot 4.7.2-stable (standard, not .NET), `--version` prints `4.7.2.stable.official.ed1daf0bf`.
- The `GODOT` environment variable points `run.sh` at the pinned binary. Never open `attimo/` with another Godot version.
- Run all smoke tests: `bash attimo/tests/run.sh`. Run one: `bash attimo/tests/run.sh test_conventions`.
- Run an editor-time script headless: `bash attimo/tests/run.sh --tool res://tools/<script>.gd`.
- Install path, checksum and credits: see `README.md`.
