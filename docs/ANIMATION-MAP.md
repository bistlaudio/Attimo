# Animation map (MOVE-11)

Which movement verb is shown by which Mannequin clip. Guarded by `attimo/tests/smoke/test_animation_map.gd`: the test fails when a state node of `player.tscn` or a clip referenced by `mannequin_tree.tres` is missing from this file, or when a referenced clip is missing from the library.

## Rules

- The source of truth is the movement FSM (`StateMachine` under `Player`). `MannequinAnimator` only presents it: it travels the animation state machine on the same call as the FSM state change and never decides movement state.
- Kit clips of `Rig_Medium` (library `res://assets/animations/rig_medium/rig_medium_library.res`, 14 clips) are used, plus retargeted external clips listed in "External clips" below (DEV-04, quick 261118-qbt), plus cuts, blends, playback speed and procedural rotation. There are no hand-keyed clips in this phase.
- The animation root is an `AnimationNodeBlendTree` generated by `tools/build_mannequin_tree.gd` into `scenes/player/mannequin_tree.tres`: StateMachine -> TimeScale -> Land -> Aim -> output. Never edit the `.tres` by hand.
- Lean and pirouette are not clips. `ProceduralPose` writes them as code rotation on the `Mannequin` child of `VisualRoot` (DEV-01); see `docs/CONVENTIONS.md`.
- Aim mode (hold `aim`) adds an upper-body layer and a different locomotion blend; it never changes the FSM states.

## States and nodes

FSM states under `Player/StateMachine`: `Idle`, `Jump`, `LongJump`, `Run`, `Fall`, `Dash`.

Animation state machine nodes: `Locomotion`, `Jump`, `Fall`, `Dash`, `DashLeft`, `DashRight`, `DashBack`, `Slide`.

Kit clips in use (all in the library): `Idle_A`, `Running_A`, `Running_Strafe_Left`, `Running_Strafe_Right`, `Walking_Backwards`, `Jump_Start`, `Jump_Idle`, `Jump_Land`, `Dodge_Forward`, `Dodge_Left`, `Dodge_Right`, `Dodge_Backward`, `Ranged_1H_Aiming`.

Retargeted external clips in use (also in the library): `Running_Slide`.

## External clips

Clips that do not come from the KayKit Rig_Medium pack are retargeted onto `Rig_Medium` in code (DEV-04, also a deviation from FOUND-05 "kit clips only"). They are baked into the same library, so the animation tree and the tests treat them like kit clips.

| Clip | Family | Raw source (reference library, local) | Conformed file (committed) | Window |
|---|---|---|---|---|
| `Running_Slide` | `mixamo` | `KayKit/Mixamo/Running Slide.fbx` | `attimo/assets/animations/external/mixamo/running_slide.scn` | Node `Slide`: 0.0667 s to 0.4 s (0.3333 s), the drop into the low pose, played in `dash_time` (1.85x). Hips at 102 % of rest at the start, 60 % at the end (measured). |

The raw Mixamo download is not committed (`KayKit/Mixamo/*.fbx` is in `.gitignore`; Mixamo terms allow embedding in the game, not standalone redistribution). Only the mesh-free conformed scene is tracked. A fresh checkout can run everything except `tools/conform_external_clip.gd`, which needs the raw file.

The retarget path is `tools/clip_retargeter.gd`: a `BoneMap` on `SkeletonProfileHumanoid` is the pivot vocabulary, one map per source family (`mixamo`, `ual` for the Quaternius Universal Animation Library, `rig_medium` for the round-trip test). Rotations are transferred through character-space bone directions, so a T-pose and an A-pose source both work. The hips stay in place (`pin_horizontal`, the dash moves the body in code); the hips height follows the source's floor contact, and no foot or toes joint sinks more than 8 % of the hips height below its rest height. `test_retarget` guards the maps, a round trip, the limb direction parity and the slide depth.

Adding an external clip:

1. Put the raw file into the reference library outside the project (`KayKit/Mixamo/` for Mixamo, the UAL pack under `KayKit/Universal Animation Library[Standard]/`). FBX files never go inside `attimo/`.
2. Add a row to `ROWS` in `tools/conform_external_clip.gd` (raw path, output `.scn`, clip name) and run it: `bash attimo/tests/run.sh --tool res://tools/conform_external_clip.gd`.
3. Check that the source family map in `tools/clip_retargeter.gd` knows every bone (`mixamo` and `ual` are ready; a new family is one more const map).
4. Add a row to `RETARGETED` in `tools/build_animation_library.gd` (clip, conformed scene, family, loop, `pin_horizontal`) and run it. It prints the hips height curve of the new clip.
5. Add the `.scn` to the whitelist of `test_asset_hygiene`, the clip to `test_animation_library`, and a row to the verb table and to this section; add a state-machine node in `tools/build_mannequin_tree.gd` if a verb plays it, and run that tool.

## Left out

- Wall-run (MOVE-12) and ledge grab (MOVE-13) have no kit clip and stay out of this phase.
- Slide is no verb and no state (D-03). The unaimed ground dash only presents the retargeted `Running_Slide` clip (quick 261118-qbt, DEV-04); the FSM, the timings and the hand-offs are the dash's own.
- Sprint does not exist: there is one run speed.

## Adding a verb

A new verb lands only together with a kit clip or a composition row in this table, in the same change as its state. Add the state name, the animation node and the clip name (backticked) to the table above; `test_animation_map` fails otherwise.
