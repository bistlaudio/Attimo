# Phase 05.1 Plan 05: Slingshot Presentation and the F2 Kit Section Summary

**The slingshot cage now reads as steampunk at every cue, on the shared Loader presentation code. While it holds Rino, the crosshair shows a brass pressure gauge with its needle at the stored speed, and the trajectory preview draws one brass arc with no turquoise bonus arc, even with a full core. The "geladen" vignette is tinted brass. A steam puff shows on the catch, and on the throw a steam column blasts out against the throw direction and is gone within 0.22 s of real time. The steam cannon's 0.2 s fixed hold no longer flashes the Loader HUD: no ring, no preview, no vignette and no hum. Its launch shows a steam blast at the muzzle. The arm Loader is unchanged. A new F2 "Kit" section lists every range float of the nearest kit block's own config copy (for the cannon: fixed_hold, fixed_speed and the rest) and edits only that node.**

## Accomplishments

- `Crosshair`: the CAGE source draws `_draw_gauge`: a brass dial over 270 degrees with 7 ticks, a needle at `stored_ratio()` and a thin inner arc that fills with the hold time. It does not turn. `loader_ring_tint` is `LoaderPreview.BRASS_COLOR` whatever the core, so it is never turquoise and never the grey empty-arm colour. FIXED hides the ring. The new `loader_ring_style()` returns `&"gauge"`, `&"double"` or `&""`.
- `LoaderPreview`: CAGE draws only the no-bonus arc, in `BRASS_COLOR`. FIXED draws nothing. `arcs_drawn` and `arc_tints` are exposed because a headless run reads MultiMesh colours back as black.
- `LoaderLook`: CAGE keeps the full look with a brass vignette tint. The tint is written on every held frame, because the vignette material is shared by every instance of the scene, and it is kept for the fade-out. FIXED counts as no hold.
- `CatchLaunch`:
  - `SteamPuff` shows on every catch.
  - `SteamBlast` shows on the block's own throw: the CAGE `loader_released` fact, with the column turned against the throw as the exhaust, or the FIXED `launched` fact, with the column in the pitched Barrel at the muzzle.
  - Both cues run in real time, grow from 0.4 to 1.3 scale and hide themselves. `reset()` hides them.
  - Boost rings and bounce pads also emit `launched`. They never trigger the blast, because the block must be CAPTURING with the matching source and the fact must come from within radius + 1 m.
- Look scenes: `slingshot_core.tscn` and `steam_cannon.tscn` each have a hidden `SteamBlast` (Node3D + translucent cylinder `Plume`) and a hidden `SteamPuff` (three translucent spheres). They use the same translucent grey steam material as the cannon's static column, so MechanismLook leaves them alone. No particles.
- `TuningPanel`:
  - The Kit section has its own container after the Hand rows. Every 0.25 s of real time it finds the nearest `kit_block` within 8 m of the player, and when that block changes it rebuilds under "Kit: <node name>".
  - There is one slider per range float of the block's config, clamped to the export range.
  - A config with a `resource_path` (a shared, loaded preset) is never bound.
  - `kit_row_count()` and `set_kit_value()` mirror the hand helpers, and nothing is saved.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `Crosshair.loader_ring_style` const renamed so `loader_ring_style()` can be a method**
- **Found during:** Task 2
- **Issue:** GDScript cannot have a const and a method with the same name, and the plan names the method.
- **Fix:** The const is now `LOADER_RING_DOUBLE`, with a new `LOADER_RING_GAUGE`. The existing (s2) check in test_crosshair compares `shot_ring_style` with `LOADER_RING_DOUBLE`; only the name changed, the meaning is the same. docs/CONVENTIONS.md line 236 was updated to match. Neither file was in the plan's list for Task 2.

**2. [Test design] Preview colours read from `arc_tints`, not from the MultiMesh**
- In a headless run `MultiMesh.get_instance_color` returns black, which was measured. The preview now records the tint of each arc it draws.

**3. [Test design] Release-tick visibility recorded through a CONNECT_DEFERRED listener**
- The test's own `loader_released` listener runs before the cage's, because it connects first. The deferred listener reads `SteamBlast.visible` at the end of the release frame, before the hitstop's next physics tick. "Hidden within 0.3 s" is checked with a real-time timer that ignores the time scale.

**4. [Scope] Cannon blast check added to test_crosshair (q3)**
- The plan specifies the cannon blast in Task 2's action but has no test for it. It is in test_crosshair's cannon scenario. That scenario also clears the `launched` fact from the test's own entry push.

**5. [Design] Gauge has a thin inner hold-time arc**
- The cage still auto-throws at the 1.2 s cap, so the gauge keeps the cap readable. The needle is the stored speed, as the plan says.

**6. [Design] F2 Kit scan runs while the panel is hidden**
- The scan is bounded: every 0.25 s, one pass over the kit_block group. The section is ready when F2 opens, and opening F2 forces a scan at once. A config that still has a `resource_path` is refused (T-05.1-14).

[Tooling] gsd-sdk state handlers:** advance-plan / update-progress / roadmap ran; they blanked last_activity and left stopped_at and the "complete" range stale, so those and the three decisions were set by hand in STATE.md. requirements.mark-complete was skipped on purpose (KIT-* tick at phase end).
