## Deviations from Plan

**1. [Rule 1 - Plan bug] No second kit_launch_scale on the bounce**
- The plan formula `speed * kit_launch_scale() * amp` would scale twice: `launch_along` and `boost_along` apply the kit scale themselves. The block passes `bounce * amp` only.

**2. [Rule 1 - Design correction] BOUNCE uses landing detection, not an Area3D**
- A thin trigger tunnels at terminal speed and the tuned bounce depends on the drop height. ImpulseConfig got `restitution` and `max_speed` (profile numbers, not flags); the Volume is disabled for BOUNCE.

**3. [Rule 1 - Stale assertion] test_look_pass minimum scene count 15 -> 11** (four mechanism scenes deleted, now kit presets). No design value changed.

**4. [Rule 3] Gravity request API tests kept**
- The old low-gravity scenario also guarded the `request_gravity_scale` clamps and the dash-owned gravity_scale. The clamp checks live on in test_fields_and_zones (`_scenario_gravity_requests`), the dash-inside-zone check in test_amplification.

**5. Acceptance grep nuance**
- `grep ... BoostRing\b|BouncePad\b` also matches the plan-mandated station names `Station_BoostRing` and `Station_BouncePad` (and their labels) in the builder and gym scene. The kit scene roots are named `BoostRingLook` / `BouncePadLook`; no old class, scene or script reference remains (checked with a boundary grep that excludes only those station names).

**6. Station slots**
- Plan listed no slots: steampunk boosters use south row 1 columns 0..2, energy bounce pad core south (0, 0), gravity zone north (0, 1), each with a capsule beside it.
