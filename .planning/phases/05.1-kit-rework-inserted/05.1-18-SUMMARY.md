## Deviations from Plan

**1. [Rule 2 - Threat mitigation] Pull target speed 6.0, not the old ATTRACT 10.** The plan says "old ATTRACT numbers" and T-05.1-54 says the pull target must be below run speed (8.5). The threat register wins; accel stays 60 (below ground_accel 70, so walking out wins).

**2. [Rule 3 - Design gap] `pay_on_start` option on EnergyCost.** The plan interface has none; without it the first escape step would come 0.5 s late and a dash out at 0 steps would be free and never refuse. Core keeps the end-of-interval timing.

**3. [Rule 1 - Bug in own draft] tick() true between payments.** The core first counted every true return as a payment (paid 9 at once). EnergyCost now emits `paid(steps)` and the core counts that.

**4. [Discretion] escape_speed preset 9.5, not exactly the run speed.** Walking at 8.5 must never count as a fast escape; an equal threshold would flicker on float noise.

**5. Files edited beyond the plan list:** test_look_pass (energy core lens read from the kit scene, scene count 11 to 9), test_mechanism_influence (guard file count 10 to 6, the guard still scans every mechanism script), test_fields_and_zones (repulsor and attractor scenarios removed), `resources/kit/trigger/core_ring_off.tres` (dim ring material: the shared glow_idle is reserved for Interactable lenses by test_glow_stages), test_triggers.gd and its .uid deleted (only held the old core scenario).

**6. Station placement:** the core station uses two bridges (east at level 1, north at level 3) around the near ledge instead of one long chain, to stay within a 24 x 24 m footprint. The OR station routes the gate through a 5 s LogicTimer (a gate is only active while the player stands in it, as in 05.1-17).
