## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Gym station kind "kit" instead of "driven"**
- **Found during:** Task 3
- **Issue:** the "driven" kind adds a Driver<tag> SignalSource and sets `source` on the block; KitBlock has no `source` (D-13), so the driver would be a dead node and the set a silent no-op.
- **Fix:** new `kit` kind in `mechanism_rooms_builder.gd` (`_station_kit`: block + sign, same slot and height).
- **Files:** attimo/tools/mechanism_rooms_builder.gd

**2. [Rule 3 - Blocking] test_movement_gym did not see kit blocks**
- **Issue:** the field-station kind count skipped every non-`Mechanism` child, and the mesh-wrapper / interactable-layer rules only sanctioned `scenes/mechanisms/`.
- **Fix:** count kinds for `Mechanism` or `KitBlock` children (kit blocks skip the source wiring check), sanction `res://scenes/kit/` like `res://scenes/mechanisms/`.
- **Files:** attimo/tests/smoke/test_movement_gym.gd

**3. [Plan ambiguity] Tick numbering of the press / tap scenarios**
- The plan's "pressed at tick 5, released at tick 12 -> discharge at tick 12" is anchored to `LoaderState.update_count`: the release applied after update 12 fires on update 13 (the first update that can see it, same as the arm Loader). A tap injected by the harness inside a physics frame (after `physics_frame`, before the player's update) shows `is_action_pressed` at once but `just_pressed` / `just_released` only on the next frame (probed), so the test accepts update 6 or 7. Real input events arrive between frames and are seen on the next update.

**4. [Plan no-op] test_mechanism_rooms has no SlingshotCore reference**
- The plan asked to replace SlingshotCore checks there; there were none (only test_movement_gym had one). No edit made.

**5. [Naming] Cage root node is `SlingshotCage`**
