## Phase Goal

**As a** developer, **I want to** see the KayKit Mannequin animate on input in a Prototype Bits test scene, **so that** the project base and the prototype pipeline are proven.

This plan is the Walking Skeleton (see `.planning/phases/01-foundation-prototype-character/SKELETON.md`). It leads with the phase tracer, the thinnest path through every layer: pinned engine -> project settings -> Input Map action -> Player FSM -> EventBus fact -> headless smoke harness. `VisualRoot` is created here and stays empty in this plan. Plan 01-02 instances the Mannequin under it, which changes no architecture.

**D-09, Option A (user decision, 2026-11-04):** Phase 1 has NO movement physics. The Player never moves: no velocity, no gravity, no floor checks. Input actions only change FSM states, and the states run on timers that match the clip lengths. Phase 2 adds velocity, gravity and the single kinematic move call to the same PlayerController and states. The velocity and gravity parts of the RESEARCH code examples are therefore NOT used (see the planning note under RESEARCH "Code Examples").

<objective>
Prove end-to-end that pressing the Input Map action `jump` drives the node-based player FSM into Jump and broadcasts the `jumped` fact on the EventBus autoload. A headless smoke harness on the verified, pinned Godot 4.7.2 binary must show all of this. Then guard the engine pin and project settings and document the setup in README.md.

Purpose: Every later plan and phase builds on this path: the fact bus (D-10/D-11) for juice and audio, the FSM (D-09) for movement, and the harness for verification. Proving it first on the best early-context tokens catches an architectural dead end after one commit.
Output: pinned engine installed outside the repo, updated `attimo/project.godot`, EventBus, FSM core, PlayerController with Idle/Jump states, `player.tscn`, `tests/run.sh` plus runner plus two smoke tests, `tests/fixtures.gd`, root `README.md`.
</objective>
