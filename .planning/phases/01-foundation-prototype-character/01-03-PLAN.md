## Phase Goal

**As a** developer, **I want to** see the KayKit Mannequin animate on input in a Prototype Bits test scene, **so that** the project base and the prototype pipeline are proven.

This plan is an expansion slice. On input, the Mannequin now plays run, fall, land and dodge in place, and every verb broadcasts its fact.

**D-09, Option A (user decision, 2026-11-04):** Phase 1 has NO movement physics. Input actions only change FSM states, which run on timers matching the KayKit clip lengths. The Player never moves: no velocity, gravity, floor checks or kinematic move call. Facing turns VisualRoot toward the input direction, which needs no velocity, so it stays. Phase 2 adds speeds, gravity, real airtime and landing by floor contact to these same states. The velocity and gravity parts of the RESEARCH code examples are NOT used.

<objective>
Add the remaining demo verbs to the existing FSM, all in place and timer-driven:
- Run: Running_A with facing.
- Fall: follows Jump on a timer and emits `landed` when its timer ends, the point where the Jump_Land phase starts.
- Dash: Dodge_Forward, emits `dash_started`, from grounded and airborne states.
This completes the D-11 fact set from gameplay.

Purpose: This covers success criterion 3 (Idle, Run, Jump, Dodge clips on Input Map actions) and the gameplay half of criterion 4 (facts on the bus), strictly within D-09.
Output: updated `player_controller.gd`, `idle.gd`, `jump.gd`; new `run.gd`, `fall.gd`, `dash.gd`; three new State nodes in `player.tscn`; two smoke tests.
</objective>
